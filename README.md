# Finance Manager with Supabase

## 1. Introdução  
O Finance Manager é uma aplicação de gestão financeira pessoal desenvolvida para oferecer controle total sobre rendas, despesas, cartões de crédito e dívidas de terceiros. Para sustentar esta aplicação, foi utilizado o **Supabase** como plataforma de Backend-as-a-Service (BaaS), utilizando o **PostgreSQL** como motor de base de dados.  

## 2. A Escolha do Supabase  
O Supabase foi selecionado por oferecer uma infraestrutura robusta de nível empresarial com configuração simplificada:
* **PostgreSQL:** Base de dados relacional potente para lidar com transações financeiras.
* **Autenticação Integrada:** Gestão de utilizadores segura e simplificada.
* **Auto-generated APIs:** Criação instantânea de endpoints baseados no esquema da base de dados.
* **Row Level Security (RLS):** Segurança nativa ao nível da linha para proteção de dados sensíveis.  

## 3. Experiência com a Interface do Supabase  

### 3.1. SQL Editor (O Coração do Backend)  
O processo de construção do backend deu-se principalmente através do **SQL Editor**. Em vez de usar interfaces visuais limitadas, utilizamos scripts SQL para garantir precisão na criação de tabelas e relações.  

* **Untitled Queries:** Espaço utilizado para testar comandos de criação e alteração (ALTER TABLE) antes da implementação final.  
* **Exemplo de uso:** Criação de tabelas com chaves estrangeiras para ligar transações a cartões e devedores.  

### 3.2. Table Editor
Utilizado como ferramenta de inspeção visual. Permite verificar em tempo real se os dados inseridos pela aplicação estão a ser persistidos corretamente. Foi fundamental para diagnosticar o erro inicial onde a tabela profiles não era encontrada.  

### 3.3. Dashboard de API e Configurações
A interface de Project Settings foi utilizada para extrair as credenciais de conectividade (`URL e anon key`), que foram posteriormente integradas no ambiente de desenvolvimento através de ficheiros `.env`.  

## 4. Evolução do Esquema de Dados (Database Schema)
O projeto evoluiu de uma estrutura simples para um ecossistema financeiro completo. Abaixo, o script consolidado utilizado no Supabase de algumas tabelas existentes:

* Estrutura de Perfis e Renda

```
create table if not exists profiles (
|  id uuid references auth.users on delete cascade not null primary key,
|  full_name text,
|  avatar_url text,
|  monthly_income numeric(10, 2) default 0
);
```

* Gestão de Cartões de Crédito

```
create table if not exists credit_cards (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  name text not null,
  limit_amount numeric(10, 2),
  due_day int
);
```

* Gestão de Devedores (Empréstimos/Divisões)

```
create table if not exists debtors (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  name text not null
);
```

## Conclusão do Processo
O processo de estudo e implementação do Supabase resultou numa conexão bem-sucedida entre o front-end em **React Native/Expo** e o backend na nuvem. A aplicação agora possui uma "tubulação" de dados segura, com suporte para faturas de cartões, gestão de devedores e controle de renda mensal, estando pronta para a expansão de funcionalidades de interface.
